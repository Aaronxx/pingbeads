## 一、为什么做轮廓强化

拼豆图纸和普通像素画的关键区别：**拼豆是物理实体，没有抗锯齿**。一颗异色豆子非常扎眼，孤立杂色和模糊边界严重影响填色体验。

拼豆玩家偏好（讨论共识）：

1. **色彩集中** —— 色号数量比色彩纯度更影响体验。理想 8~15 色，复杂图也尽量 ≤20。分拣豆子本身就要半小时。
2. **线条连续、边界清晰** —— 拼豆图无抗锯齿，边界模糊会让形状难以辨识，也容易填错位。
3. **形状规则** —— 拼豆必然损失细节，必须抽象出大致形状才能体现特点。

**轮廓强化的价值**：辨识度提升的最大单点。Disney 像素画、任天堂 sprite 的经典技法——主体边缘用深色描边，让形状"跳"出来。这是优先级最高的改进。

```
原图色块:        描边强化后:
□□□□□            □□□□□
□■■■□            □■■■□   ■=主体色
□■■■□    →      □■■■□   ░=深色轮廓
□■■■□            □■■■□
□□□□□            □░░░□
```

## 二、设计要点（待恢复时确认）

### 2.1 轮廓检测策略

候选方案，优先级从高到低：

| 方案 | 思路 | 优点 | 缺点 |
|------|------|------|------|
| **A. markCode 边界** | 遍历格子，若格子与 4 邻居（或 8 邻居）的 markCode 不同，标记为轮廓 | 实现简单，复用现有 gridData；与聚类结果一致 | 对同色但明度不同的边界不敏感 |
| **B. originalRgb 边界** | 在 rawRgb 空间检测颜色变化（带阈值） | 能捕捉聚类抹平的细微边界 | 与最终呈现的 markCode 可能脱节 |
| **C. Sobel/Canny 边缘检测** | 在像素层做经典边缘检测，再映射到网格 | 边缘最精准 | 实现复杂，性能开销大，网格化后优势不明显 |

**初步倾向**：方案 A。拼豆已经网格化+聚类，再回像素层做边缘检测收益有限，且性能敏感。方案 A 直接在 `gridData` 上遍历，O(rows×cols)，与 `cleanIsolatedColors` 同构，可复用其 BFS/遍历模式。

### 2.2 轮廓颜色选择

轮廓格子替换成什么颜色？三种策略：

| 策略 | 做法 | 适用场景 |
|------|------|----------|
| **固定深色** | 统一替换为黑 `#000000` 或深灰 `#333333` | 卡通风格、强对比 |
| **主体色加深** | 取该格子原 markColor，在 HSL 空间降明度 L-20~30 | 自然过渡，不突兀 |
| **邻近最深色** | 在当前色板里找最深的色号 | 受限于色板，可能找不到合适的 |

**初步倾向**：默认"主体色加深"，保留"固定深色"作为可选模式。避免引入新色号（否则破坏聚类限色的成果）。

### 2.3 参数化（暴露给用户）

建议做成两个维度，而非单一开关：

- **轮廓强度** `outlineIntensity` (0~1, 默认 0)
  - 0 = 关闭
  - 越大 → 越多格子被判定为轮廓（通过调节"邻居差异阈值"实现）
- **轮廓颜色模式** `outlineColorMode` ('darken' | 'fixed')
  - darken = 主体色加深（默认）
  - fixed = 固定深色

或者更省事的方案：**3 档预设**「关 / 弱 / 强」，每档背后是一组参数组合。用户不用懂参数。

## 四、后续改进方向（讨论中提出，非本轮范围）

按优先级：

1. **轮廓强化**（本文档）—— 优先做，辨识度提升最大
2. **色块合并** —— 合并同色号的碎片色块（比 cleanIsolatedColors 更激进，按"同色+小面积+邻近色"合并）
3. **杂色清理强度滑块** —— 把 cleanIsolatedColors 的 minArea 暴露成滑块
4. **对称化后处理** —— 强制左右镜像，消除原图不对称噪声（适合对称图案）
5. **购买清单冗余系数** —— CSV 导出加 10~15% 冗余并标注"建议购买量"
