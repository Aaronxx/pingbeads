# 拼豆酥小程序 - 性能优化方案

> 生成日期：2026-06-09
> 基于对项目代码的全面分析，共识别 5 个可优化热点，每个方案独立一个 git 分支。

---

## 总览

| 分支 | 优先级 | 优化内容 | 预期收益 | 风险 |
|------|--------|---------|---------|------|
| `opt/canvas-node-cache` | P0 | 缓存 canvas 节点引用 | 渲染延迟降低 10-30ms/次 | 低 |
| `opt/touchmove-setdata` | P0 | touchmove 中节流 setData | 拖动帧率提升 | 低 |
| `opt/observer-debounce` | P1 | observer 防抖 + 有界重试 | 消除连锁反应和无效轮询 | 低 |
| `opt/canvas-size-tiered` | P1 | 预览图/导出图按设备分级 | 低端设备内存降 75% | 低 |
| `opt/memory-cleanup` | P2 | 低端设备释放像素缓存 | 减少 OOM 崩溃 | 中 |

### 测试建议

- `opt/canvas-node-cache`：多次切换图片后 canvas 是否正常渲染

## 一、opt/canvas-node-cache（P0）

### 问题

`renderToCanvas` 和 `renderSegmentsToCanvas` 每次调用都执行 `createSelectorQuery().exec()`，这是一次异步 IPC（逻辑层 → 渲染层）。整个组件有 18+ 个调用点，每次都重复查询同一个 canvas 节点。

**原代码：**
```javascript
renderToCanvas(gridData, cols, rows, gridSize) {
  const query = this.createSelectorQuery();
  query.select('#mosaic-render-canvas')
    .fields({ node: true, size: true })
    .exec((res) => {
      if (!res[0] || !res[0].node) {
        setTimeout(() => that.renderToCanvas(...), 200);
        return;
      }
      const canvas = res[0].node;
      // ... 渲染逻辑
    });
}
```

### 优化方案

将渲染拆分为三步：

1. `renderToCanvas`：先检查 `this.canvasNode` 缓存，有效则直接进入渲染（同步路径）
2. `_queryCanvasNode`：仅首次或缓存失效时异步查询，缓存结果到 `this.canvasNode`
3. `_doRenderToCanvas`：实际渲染逻辑

**优化后：**
```javascript
renderToCanvas(gridData, cols, rows, gridSize) {
  this.isRendering = true;
  // 优先复用缓存
  if (this.canvasNode && this.canvasCtx) {
    this._doRenderToCanvas(gridData, cols, rows, gridSize);
    return;
  }
  // 首次查询
  this._queryCanvasNode(() => {
    this._doRenderToCanvas(gridData, cols, rows, gridSize);
  });
}
```

### 涉及方法

- `renderToCanvas` → 拆分为 `renderToCanvas` + `_queryCanvasNode` + `_doRenderToCanvas`
- `renderSegmentsToCanvas` → 同样拆分，复用 `_queryCanvasNode`

### 预期收益

- 每次渲染省去一次异步 IPC，延迟降低 10-30ms
- 18+ 个调用点全部受益

## 二、opt/touchmove-setdata（P0）

### 问题

touchmove 事件频率可达 60-120Hz，每次事件都调用 `setData`：

```javascript
// 双指缩放 — 每帧 setData 3 个字段
this.setData({ scale: newScale, offsetX: newOffsetX, offsetY: newOffsetY });

// 单指拖动 — 每帧 setData 3 个字段
this.setData({ offsetX: newOffsetX, offsetY: newOffsetY, lastTouch: current });
```

每次 setData 都会触发：
1. 逻辑层 → 渲染层的数据序列化传输
2. 触发 `scale` / `offsetX,offsetY` observer

### 优化方案

**改动 1：`lastTouch` 移出 data**

改用实例属性 `this._lastTouch`，不经过 setData。`lastTouch` 仅用于 delta 计算，不需要触发 WXML 更新。

**改动 2：节流 setData**

将 offsetX/offsetY/scale 累积到 `_pending*` 实例属性，通过 16ms 定时器节流（约 60fps）：

```javascript
handleTouchMove(e) {
  // ... 纯计算，不做 setData
  this._pendingOffsetX = newOffsetX;
  this._pendingOffsetY = newOffsetY;

  // 节流：每帧最多一次 setData
  if (!this._touchSetDataTimer) {
    this._touchSetDataTimer = setTimeout(() => {
      this._touchSetDataTimer = null;
      this.setData({
        offsetX: this._pendingOffsetX,
        offsetY: this._pendingOffsetY
      });
    }, 16);
  }
}
```

**改动 3：touchEnd 一次性同步**

所有最终状态在 touchEnd 一次 setData 同步到 data，触发 observer 和 canvas 渲染。

### 预期收益

- setData 频率从 60-120Hz 降至 ~60Hz
- 每次传输字段数减少（去掉 lastTouch）
- 拖动/缩放更流畅

## 三、opt/observer-debounce（P1）

### 问题

**问题 1：主参数 observer 无防抖**

```javascript
'gridSize, mergeThreshold, previewQuality, processMode': function() {
  // 直接处理，滑块快速拖动时每次都触发
  this.regenerateFromCache();
}
```

当 index.js 中 `onGridSizeChange` 一次 `setData` 修改 6 个字段时，可能触发重复处理。

**问题 2：6 个 observer 使用无限 setTimeout 轮询**

```javascript
'useSpecialColors': function() {
  const tryApply = () => {
    if (this.cachedGridData && this.cachedGridInfo) {
      // 执行
    } else {
      setTimeout(tryApply, 100);  // 无限轮询！
    }
  };
  tryApply();
}
```

极端情况下 setTimeout 队列无限堆积。

### 优化方案

**改动 1：主参数 observer 增加 150ms 防抖**

```javascript
'gridSize, mergeThreshold, previewQuality, processMode': function() {
  if (this._paramDebounceTimer) clearTimeout(this._paramDebounceTimer);
  this._paramDebounceTimer = setTimeout(() => {
    this._paramDebounceTimer = null;
    this._doReprocess();
  }, 150);
}
```

**改动 2：新增 `_waitForData` 辅助方法，替代无限轮询**

```javascript
_waitForData(callback, retryCount) {
  retryCount = retryCount || 0;
  if (this.cachedGridData && this.cachedGridInfo) {
    const { rows, cols, gridSize } = this.cachedGridInfo;
    callback.call(this, rows, cols, gridSize);
    return;
  }
  if (retryCount >= 10) {  // 最多 10 次 × 100ms = 1 秒超时
    console.warn('[mosaicCanvas] 等待数据就绪超时');
    return;
  }
  setTimeout(() => this._waitForData(callback, retryCount + 1), 100);
}
```

影响的 observer：`useSpecialColors`、`removeEdge`、`mirrorImage`、`vibrantScale`。

### 预期收益

- 滑块快速拖动时只在停止后才处理，避免重复计算
- 消除极端情况下的 setTimeout 无限堆积

## 四、opt/canvas-size-tiered（P1）

### 问题

预览图 Canvas 固定最大 16384px，低端设备上：
- 16384×16384×4 bytes ≈ **1GB 内存**
- 极易触发 OOM 崩溃

### 优化方案

根据 `wx.getSystemInfoSync().benchmarkLevel` 分三档：

| 设备等级 | benchmarkLevel | 预览图上限 | 导出图上限 |
|---------|---------------|-----------|-----------|
| 高端 | ≥ 200 | 16384px | 8192px |
| 中端 | 100-199 | 8192px | 4096px |
| 低端 | < 100 | 4096px | 4096px |

**预览图**（`mosaicCanvas.js` 中 `renderToCanvas` + `renderSegmentsToCanvas`）：

```javascript
const sysInfo = wx.getSystemInfoSync();
const benchmarkLevel = sysInfo.benchmarkLevel || 10;
let MAX_CANVAS_DIMENSION;
if (benchmarkLevel >= 200) {
  MAX_CANVAS_DIMENSION = 16384;
} else if (benchmarkLevel >= 100) {
  MAX_CANVAS_DIMENSION = 8192;
} else {
  MAX_CANVAS_DIMENSION = 4096;
}
```

**导出图**（`index.js` 中 `exportPNG`）：

```javascript
const sysInfo = wx.getSystemInfoSync();
const benchmarkLevel = sysInfo.benchmarkLevel || 10;
let maxExportDimension;
if (benchmarkLevel >= 200) {
  maxExportDimension = 8192;   // 高端设备：更高清导出
} else {
  maxExportDimension = 4096;   // 其他：保持原值
}
```

### 影响分析

- **scale≤2 的正常使用**：不受影响（canvas 不触发上限）
- **scale≥4 高倍缩放**：中低端设备预览略模糊，但手机上仍清晰可读
- **导出图**：高端设备导出更清晰，其他设备不变

## 五、opt/memory-cleanup（P2）

### 问题

组件同时持有三份大数据缓存：

| 属性 | 内容 | 1080p 图片大小 |
|------|------|--------------|
| `cachedPixelData` | 原始 RGBA 像素 | 1080×1920×4 ≈ 8MB |
| `cachedOriginalGridData` | 原始网格快照 | 取决于 cols×rows |
| `cachedGridData` | 当前工作网格 | 取决于 cols×rows |

`cachedPixelData` 用于参数变化时快速重新处理，但在低端设备上 8MB 压力较大。

### 优化方案

在 `_finishMosaicResult` 和 `_finishSimpleResult` 完成后，调用 `_maybeReleasePixelData()`：

```javascript
_maybeReleasePixelData() {
  if (!this.cachedPixelData) return;

  const sysInfo = wx.getSystemInfoSync();
  const benchmarkLevel = sysInfo.benchmarkLevel || 10;

  // 仅低端设备释放（benchmarkLevel < 50）
  if (benchmarkLevel < 50) {
    const sizeMB = (this.cachedPixelData.length / 1024 / 1024).toFixed(1);
    console.log(`[mosaicCanvas] 低端设备释放像素缓存 (${sizeMB}MB)`);
    this.cachedPixelData = null;
  }
}
```

### 回退路径

释放 `cachedPixelData` 后，参数变化时 observer 会走 `else if (this.data.imagePath)` 分支，从磁盘重新读取图片。`processImage` 方法已支持此路径，功能不受影响，只是重新处理会慢几百毫秒。

### 预期收益

- 低端设备节省约 8MB 内存
- 减少 OOM 崩溃概率
