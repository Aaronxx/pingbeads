# 聚类算法优化总结

> 分支：`feat/color-aggregation-and-anti-gray`
> 基线：`4c07c40`（master）
> 归档标签：`v0.5-aggregation-comparison`（含三种算法对比代码）

本分支围绕"卡通模式限色聚合"做了系统性优化，目标是让**甜区（15-30 色）的色彩还原度和整合度都达到可用水平**。过程中经历了多次方案迭代、踩坑、回退和最终定型。

---

## 一、最终算法：加权最远点 K-means + 多重色彩保护

### 核心流程（`aggregateSimilarColors`）

```
1. 收集所有格子的 originalRgb，去重统计 → uniqueColors[]
2. 初始化聚类中心（加权最远点）：
   - 首个中心 = count 最大的点（主体色）
   - 后续中心 = count^COUNT_WEIGHT_EXP × D² 最大的点
     （D = 到已有中心的最近距离，含色彩保护）
3. Lloyd 迭代（MAX_ITERATIONS 轮）：
   - 分配：每个色归到最近中心（距离含色彩保护）
   - 更新：簇内 count 加权平均 RGB → 新中心
   - 收敛：中心移动距离² > CONVERGE_THRESHOLD 则继续
4. snap：簇中心 → Mark 色（彩色中心跳过浊色）
5. 回写：每格的 markCode/markHex/markRgb 改为簇代表色
```

### 多重色彩保护（`euclideanDistanceSqProtected`）

这是本分支的核心创新，防止颜色被错误合并。三重保护：

| 保护 | 触发条件 | 解决的问题 |
|---|---|---|
| **饱和度差** | 双方饱和度差 >0.12 且高饱和方 >0.18 | 鲜艳色被浊色/灰色吸收（浅蓝变灰、粉变 M10）|
| **色相差** | 双方都有色相且色相差 >HUE_DIFF_THRESHOLD | 冷色变暖色（浅蓝变浅黄）|
| **明度差** | 明度差 >40 且占高明度比例 >35% | 亮色被暗色拉低（粉红变深灰）|

### snap 阶段浊色过滤（`findClosestMarkColorSkipMuddy`）

簇中心 snap 到 Mark 色时，若中心是彩色（饱和度 >0.15），跳过中明度浊色（`isMuddyMarkColor`：饱和度 <0.15 且明度 70-225），从根源避免彩色簇被 snap 到 M10/H11 等脏色。

## 二、可调参数（默认值为均衡偏向还原度）

位于 `imageProcessor.js` 顶部，可通过 `setAggregationParams()` 运行时调整：

| 参数 | 默认值 | 滑块范围 | 作用 |
|---|---|---|---|
| `CHROMA_PENALTY` | 0.35 | 0-100（÷100）| 色彩保护总强度（饱和度+色相+明度）|
| `COUNT_WEIGHT_EXP` | 1.0 | 5-15（÷10）| count 权重指数，整合/还原核心旋钮 |
| `MAX_ITERATIONS` | 6 | 3-10 | K-means 最大迭代次数 |
| `CONVERGE_THRESHOLD` | 15 | 4-25 | 收敛距离平方阈值 |
| `HUE_DIFF_THRESHOLD` | 28 | 20-45 | 色相保护触发门槛（度）|

**调参指南**：
- 浅彩色被吞 → 拉高"色相保护"
- 杂色太多 → 拉高"整合/还原"（count 权重）
- 整体灰暗 → 配合"浊色规避"滑块（colorMapper 的 antiGrayIntensity）

## 三、关键 Bug 修复

### 1. gridPreset observer 丢失聚合结果（`1aca004`）

**现象**：切换聚类算法后，预览变了但导出图不变（三次导出完全相同）。

**根因**：`gridPreset` observer 在默认预设分支（targetCols=0）用 `cachedOriginalGridData`（聚合前快照）恢复 `cachedGridData`，**不重新聚合**。切换算法时间接触发该路径，覆盖了聚合结果。

**诊断过程**（经典的分层定位）：
1. 加日志确认聚合是否被调用 → 是
2. 加日志确认聚合 uniqueColors/targetCount → 正常（没早返回）
3. 加日志确认聚合回写后色数 → **28 色**（正确）
4. 但导出时是 **68 色** → 聚合结果被覆盖
5. 定位到 gridPreset observer 的默认分支

**修复**：默认预设分支恢复快照后，重跑 `reapplyVibrantScale`（含聚合）；observer 加 undefined 防御。

### 2. 双重聚合消除（`0d2472d`）

**现象**：`processSimple` 内部聚合一次，`reapplyVibrantScale` 又聚合一次，第二次覆盖第一次。

**修复**：删除 `processSimple` 内的聚合调用，统一由 `reapplyVibrantScale` 负责。同时修复 vibrant=0 时漏聚合的 bug。

### 3. 功能面板手势冲突（`5306109`）

**现象**：功能面板内容区上滑会触发面板缩小，导致功能消失无法操作。

**根因**：`settings-panel` 外层绑定了 `bindtouchmove`，内部 scroll-view 的滑动冒泡触发 `isPanelMinimized`。

**修复**：拖动事件从外层移到 `panel-handle`（指示条），用 `catchtouch*` 阻止冒泡。

## 四、方案演进历程

### 阶段 1：方案 C（Mark 色空间聚类）— 失败

最初想"直接在 291 色 Mark 板上挑代表色"，消除 raw RGB → 中心 → snap 的双重映射损失。

**结果**：在 Node 环境测试正常，但在小程序环境产生**大面积灰色异常**（无法复现，但实测确认）。**放弃**。

**教训**：Node 环境和小程序环境的差异（可能是对象属性、数值精度、Map 迭代顺序）会导致同一份代码结果不同。重大重构必须在小程序实测。

### 阶段 2：多算法对比 — 定型加权最远

保留旧版（raw RGB 空间 K-means）作为基础，对比三种初始化策略：

| 算法 | 初始化 | 整合度 | 还原度 | 结论 |
|---|---|---|---|---|
| 老算法 | 空间顺序采样 | 中 | 好 | 整合度一般 |
| 欧氏·最远点 | 纯最远点 | 好 | 差 | 浅彩色被吞 |
| **欧氏·加权最远** | count×D² | 中 | 好 | **最佳平衡** ✅ |
| redmean | （任何）| 差 | 差 | 绿通道权重 ×4 导致偏色，**删除** |

**最终定型**：加权最远 + 欧氏距离 + 色彩保护。详见 tag `v0.5-aggregation-comparison`。

### 阶段 3：色彩保护体系 — 逐步完善

通过用户提供的真实图反馈，逐层发现并修复色彩丢失问题：

1. **色相差保护**：浅蓝（200°）变浅黄（40°）→ 加色相差惩罚
2. **明度差保护**：粉红变深灰（和暗紫红混簇）→ 加明度差惩罚
3. **饱和度连续保护**：粉色变 M10（浊色饱和度 0.10 卡在二分阈值中间）→ 二分判定改连续
4. **snap 跳浊色**：即使聚类正确，snap 仍可能落到浊色 → 彩色中心跳过浊色 snap

## 五、浊色规避功能（默认关闭）

独立于聚类算法的附加功能（`colorMapper.js` + `desaturateGrayColors`）：

- **源头惩罚**（方案 X）：`buildColorLookupTable` 距离公式加浊度惩罚项，强度由 `antiGrayIntensity` 控制
- **后处理替换**（方案 Y）：`desaturateGrayColors` 把浊色格子替换为非浊色邻居（借鉴 `cleanIsolatedColors` 结构）

**状态**：默认关闭（`antiGrayIntensity=0`）。实测发现默认开启时在某些场景影响稳定性，且对"本身灰暗的图"效果有限。需要时通过 UI 滑块开启。

**适用场景**：原图本身偏灰暗（如光照不足的实拍图），开启可让浊色偏向鲜艳或深色。

## 九、遗留问题与注意事项

1. **Node 与小程序环境差异**：本分支多次出现"Node 测试正常，小程序异常"的情况（方案 C 灰色、参数效果不敏感）。**任何算法改动必须在小程序实测**。

2. **本身灰暗的图**：聚类算法无法让"原图就灰暗"的图变鲜艳（72% 灰像素的图，聚合后仍灰）。需要配合浊色规避滑块，或接受原图特性。

3. **诊断日志**：当前 `findClosestMarkColorSkipMuddy` 仍含 `[snap诊断]` 日志（用于验证），确认无误后应清理。

4. **性能**：聚类对大图（>10000 格）有轻微开销，但 5-6 轮迭代 + uniqueColors 去重后通常 <500ms。colorMapper 查找表重建约 54ms。
