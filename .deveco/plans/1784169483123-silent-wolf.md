### Fix 1: Bug 2 — `_getDragLimits` 参数化，双指缩放时传入 newScale

**文件**: `src/components/mosaicCanvas/mixins/interaction.js`

**问题**: `handleTouchMove` 双指分支中，`_getDragLimits()` 用 `this.data.scale`（旧值）计算限制范围，但 offset 是基于 `newScale`（新值）算的，导致 pinch 期间 clamp 范围与实际 scale 不匹配，图片被拖出可见区域。

**修改**:
1. `_getDragLimits()` 加 `targetScale` 可选参数，默认用 `this.data.scale`：
```js
_getDragLimits(targetScale) {
  const scale = targetScale != null ? targetScale : (this.data.scale || 1);
  // ... 其余不变
}
```
2. 双指分支改为 `_getDragLimits(newScale)`：
```js
const limits = this._getDragLimits(newScale);
newOffsetX = Math.max(limits.minX, Math.min(limits.maxX, newOffsetX));
newOffsetY = Math.max(limits.minY, Math.min(limits.maxY, newOffsetY));
```

**Commit**: `fix: 双指缩放时拖动限制使用新 scale 值`

### Fix 2: Bug 3 — `_getDragLimits` 用实际渲染尺寸

**文件**: `src/components/mosaicCanvas/mixins/interaction.js`

**问题**: `_getDragLimits()` 用 `this.data.canvasWidth` 计算限制，但这个值可能与 wrapper 实际渲染宽度不一致（尤其首次渲染、设备 dpr 差异时），导致放大到很大时边缘出现空白。

**修改**: `_getDragLimits` 使用 `boundingClientRect` 获取 wrapper 实际可见区域尺寸。但 `boundingClientRect` 是异步的，不能在 `handleTouchMove` 同步调用中用。

**替代方案**: 在 `handleTouchStart` 中缓存 wrapper 尺寸，`_getDragLimits` 使用缓存值。如果缓存不可用，fallback 到 `this.data.canvasWidth`。

```js
handleTouchStart(e) {
  // ... 现有逻辑 ...
  // 缓存可见区域实际尺寸
  if (!this._viewportSize) {
    this._cacheViewportSize();
  }
},

_cacheViewportSize() {
  const query = this.createSelectorQuery();
  query.select('#mosaic-wrapper').boundingClientRect();
  query.exec((res) => {
    if (res[0]) {
      this._viewportSize = { width: res[0].width, height: res[0].height };
    }
  });
},

_getDragLimits(targetScale) {
  const scale = targetScale != null ? targetScale : (this.data.scale || 1);
  const viewportWidth = this._viewportSize ? this._viewportSize.width : (this.data.canvasWidth || 300);
  const viewportHeight = this._viewportSize ? this._viewportSize.height : (this.data.canvasHeight || 300);
  // 用 viewportWidth/viewportHeight 替代 canvasWidth/canvasHeight
  const imageWidth = viewportWidth * scale;
  const imageHeight = viewportHeight * scale;
  const overflowX = imageWidth - viewportWidth;
  const overflowY = imageHeight - viewportHeight;
  // ... 其余逻辑不变
}
```

同时在 `handleTouchEnd` 中更新缓存（尺寸可能因 resize 变化），并在 `resetPreviewState` 中清缓存。

**Commit**: `fix: 拖动限制使用 wrapper 实际渲染尺寸而非 canvasWidth`

### Fix 5: Bug 10 — `_snapshotRange` 清理不完整

**文件**: `src/pages/index/index.js`

**问题**: `_snapshotRange` 在 `exportPNG` 的 canvas 回调成功/失败中清理，但如果 `exportPNG` 在设置 `_snapshotRange` 后、canvas 查询前就 early return（比如 `getExportData` 返回 null），`_snapshotRange` 残留会影响后续正常导出。

**修改**: 在 `exportPNG` 入口处保存 `_snapshotRange` 到局部变量，在所有 early-return 路径都清理 `this._snapshotRange = null`。

具体位置：`exportPNG()` 方法中，现有 early-return 点有：
1. `!this.data.mosaicData` → 加 `this._snapshotRange = null`
2. `!mosaicCanvas || !mosaicCanvas.getExportData` → 加 `this._snapshotRange = null`
3. `!exportData || !exportData.gridInfo` → 加 `this._snapshotRange = null`
4. `!gridData && !segments` → 加 `this._snapshotRange = null`

更干净的做法：在方法开头 `const snapshotRange = this._snapshotRange;`，然后所有 early-return 前统一清理。

**Commit**: `fix: 快照导出参数在所有 early-return 路径清理`

### Fix 6: Bug 4/5/6 — 重写 `exportSnapshot` 坐标计算

**文件**: `src/pages/index/index.js`

**问题**: 
- Bug 4: `boundingClientRect` 对有 transform 的 container 返回变换后视觉尺寸
- Bug 5: `centerPhysX` 坐标系混淆（视觉像素 vs CSS 像素 vs Canvas 位图像素）
- Bug 6: 完全忽略了用户拖动偏移 `this.data.offsetX/offsetY`

**修改**: 重写 `exportSnapshot` 的坐标映射逻辑。核心思路：

1. 不用 container 的 `boundingClientRect`（它被 transform 变了），只用 wrapper 的
2. wrapper 的 `boundingClientRect` 就是可见区域的屏幕坐标
3. 用户看到的是 CSS transform 后的效果，需要把「屏幕上可见的矩形」逆映射回 grid 坐标

逆映射公式：
- 屏幕上点 (screenX, screenY) 对应的 CSS 坐标 = ((screenX - containerScreenCenter.x) / scale + containerCSSCenter.x, ...)
- 其中 containerScreenCenter = container 变换后的视觉中心

更简单的做法：用 wrapper 的 rect 和已知的 scale/offset 参数直接算：

```
wrapper 屏幕矩形 = wrapperRect (boundingClientRect, 无 transform)
container 屏幕矩形 = containerRect (有 transform, 包含 scale 和 offset)

可见区域在 container 坐标系中的范围:
  container CSS 宽高 = canvasWidth, canvasHeight
  container 视觉宽高 = canvasWidth * scale, canvasHeight * scale
  container 视觉左上角 = containerRect.left, containerRect.top

  wrapper 视觉左上角 = wrapperRect.left, wrapperRect.top
  wrapper 视觉宽高 = wrapperRect.width, wrapperRect.height

  wrapper 在 container 视觉坐标中的位置:
    visX = wrapperRect.left - containerRect.left
    visY = wrapperRect.top - containerRect.top

  转换到 container CSS 坐标 (逆 scale):
    cssX = visX / scale
    cssY = visY / scale

  但还需要考虑 translate(offsetX, offsetY) 的影响:
    CSS transform = translate(ox, oy) scale(s)
    等效：元素先 scale，再 translate(ox, oy)（在屏幕空间）
    
    container 变换后视觉位置 = container CSS位置 + (ox, oy) + scale偏移
    
    更准确：用 transform-origin: center center 的完整公式
    元素 CSS 中心 = canvasWidth/2, canvasHeight/2
    scale 后视觉中心 = CSS中心 * scale ... 不对
    
    实际 transform-origin: center center 的效果：
    元素先绕自身中心 scale，再 translate
    视觉中心 = (canvasWidth/2 + ox, canvasHeight/2 + oy)
    视觉左上角 = (canvasWidth/2 + ox - canvasWidth*scale/2, canvasHeight/2 + oy - canvasHeight*scale/2)

  container 视觉左上角:
    contVisLeft = canvasWidth/2 + offsetX - canvasWidth*scale/2
    contVisTop = canvasHeight/2 + offsetY - canvasHeight*scale/2
    
    但这是在「container 父元素坐标系」中的，即 wrapper 的 CSS 坐标系
    因为 boundingClientRect 返回的是屏幕绝对坐标，需要减去 wrapper 的位置
```

这个推导太复杂了，换一个更直接的方法：

**用两个 rect 的差值直接算可见区域在 container 内的 CSS 坐标**：

```js
// container 被变换了，boundingClientRect 是变换后的视觉尺寸
// wrapper 没有变换，boundingClientRect 是实际可见区域

// 可见区域在 container 视觉坐标中的偏移
const visOffsetX = wrapperRect.left - containerRect.left;
const visOffsetY = wrapperRect.top - containerRect.top;

// container 视觉尺寸 = canvasWidth * scale
// 转换到 container CSS 坐标（逆 scale）
const cssVisLeft = visOffsetX / scale;
const cssVisTop = visOffsetY / scale;
const cssVisWidth = wrapperRect.width / scale;
const cssVisHeight = wrapperRect.height / scale;
```

然后在 container CSS 坐标系中，grid 的位置由 renderToCanvas 的 baseOffset 决定：

```js
// grid 在 canvas 内的位置（与 renderToCanvas 一致）
const cellSize = gridSize * scale;  // 这里的 scale 是 baseScale (canvas适配scale)，不是 userScale
// ... 需要区分 canvas 内部的 baseScale 和 CSS 的 userScale
```

**实际上最可靠的方案是**：直接在 mosaicCanvas 组件中加一个方法 `getVisibleGridRange()`，它用 `this.data.scale / this.data.offsetX / this.data.offsetY / this.data.canvasWidth` + canvasNode 的内部参数来算，因为这些参数都在组件内部，不需要跨组件猜参数。

**具体实现**:

在 `interaction.js` (或 `imageProcessing.js`，已有 `getVisibleRange` 基础) 中添加：

```js
getVisibleGridRange() {
  const query = this.createSelectorQuery();
  query.select('#mosaic-wrapper').boundingClientRect();
  query.select('#canvas-container').boundingClientRect();
  
  return new Promise((resolve) => {
    query.exec((res) => {
      const wrapperRect = res[0];
      const containerRect = res[1];
      if (!wrapperRect || !containerRect || !this.cachedGridData || !this.cachedGridInfo) {
        resolve(null);
        return;
      }
      
      const { cols, rows, gridSize } = this.cachedGridInfo;
      const scale = this.data.scale || 1;
      const canvasWidth = this.data.canvasWidth || 300;
      const canvasHeight = this.data.canvasHeight || 300;
      const offsetX = this.data.offsetX || 0;
      const offsetY = this.data.offsetY || 0;
      
      // container 视觉中心 (transform-origin: center + translate)
      const contVisCenterX = containerRect.left + containerRect.width / 2;
      const contVisCenterY = containerRect.top + containerRect.height / 2;
      
      // container CSS 中心 = canvasWidth/2, canvasHeight/2
      // CSS transform: translate(ox, oy) scale(s) with origin center
      // => 视觉中心 = CSS中心 + (ox, oy) 在 wrapper 坐标系中
      // => 视觉中心 = (canvasWidth/2 + ox, canvasHeight/2 + oy) 相对 wrapper
      
      // 可见区域在 wrapper 坐标系中的范围
      const visLeft = wrapperRect.left;  // 这些是屏幕坐标
      const visTop = wrapperRect.top;
      const visRight = wrapperRect.left + wrapperRect.width;
      const visBottom = wrapperRect.top + wrapperRect.height;
      
      // 映射到 container 的 CSS 坐标系（逆变换）
      // container CSS 坐标 = (视觉坐标 - container视觉中心) / scale + containerCSS中心
      const contCSSCenterX = canvasWidth / 2;
      const contCSSCenterY = canvasHeight / 2;
      // container 视觉中心在屏幕上的位置
      // 因为 transform-origin: center center + translate(ox, oy) scale(s)
      // 视觉中心 = wrapper左上角 + contCSSCenter + (ox, oy)
      // 不对，需要更仔细地推
      
      // 换个思路：直接用 containerRect 和 scale 逆推
      // containerRect 是变换后的，width = canvasWidth * scale, height = canvasHeight * scale
      // containerRect.left = container在屏幕上的视觉左边缘
      
      // container CSS 左边缘 (0,0) 在屏幕上的位置:
      // transform-origin center => CSS 点 (x,y) 的屏幕位置:
      //   screenX = containerRect.left + (x - canvasWidth/2) * scale + canvasWidth*scale/2
      //   简化: screenX = containerRect.left + x * scale ... 不对
      //
      // 正确推导: transform-origin center center
      //   T = translate(ox,oy) * scale(s) with origin (W/2, H/2)
      //   等效: translate(ox,oy) * translate(W/2, H/2) * scale(s) * translate(-W/2, -H/2)
      //   对 CSS 点 (x, y):
      //     p1 = (x - W/2, y - H/2)           // 移到原点
      //     p2 = (p1.x * s, p1.y * s)          // 缩放
      //     p3 = (p2.x + W/2 + ox, p2.y + H/2 + oy)  // 移回 + translate
      //   屏幕位置 = wrapper.left + p3.x, wrapper.top + p3.y
      //   但 wrapper 也有位置...
      
      // 简化：假设 wrapper 左上角在屏幕 (wx, wy) = wrapperRect.left, wrapperRect.top
      // container CSS 左上角 (0,0) 的屏幕位置:
      //   = (wx + (0 - W/2)*s + W/2 + ox, wy + (0 - H/2)*s + H/2 + oy)
      //   = (wx - W*s/2 + W/2 + ox, wy - H*s/2 + H/2 + oy)
      //   = (wx + W*(1-s)/2 + ox, wy + H*(1-s)/2 + oy)
      
      const contScreenLeft = wrapperRect.left + canvasWidth * (1 - scale) / 2 + offsetX;
      const contScreenTop = wrapperRect.top + canvasHeight * (1 - scale) / 2 + offsetY;
      
      // 可见区域屏幕范围映射到 container CSS 坐标:
      // CSS_x = (screenX - contScreenLeft) / scale
      const cssLeft = (visLeft - contScreenLeft) / scale;
      const cssTop = (visTop - contScreenTop) / scale;
      const cssRight = (visRight - contScreenLeft) / scale;
      const cssBottom = (visBottom - contScreenTop) / scale;
      
      // CSS 坐标映射到 grid 坐标 (复用 renderToCanvas 的公式)
      // 这个需要知道 canvas 内部的 baseScale 和 baseOffset
      // ... 这部分依赖 canvasNode 的内部渲染参数
    });
  });
}
```

**但这里有个根本问题**：CSS transform 中的 scale/offset 与 Canvas 内部的 baseScale/baseOffset 是两套独立的坐标系。CSS transform 控制「整个 canvas 元素在页面上的视觉位置」，Canvas 内部 baseScale/baseOffset 控制「grid 数据绘制到 canvas 位图上的位置」。

快照导出需要的是：**屏幕上可见的 grid 区域 → 对应 gridData 的哪些行列**。

更直接的方案是：

1. 用 CSS 逆变换得到「可见区域在 container CSS 坐标系中的范围」
2. 再用 renderToCanvas 的映射公式（已知：baseScale, baseOffsetX, cellSize 等）把 CSS 坐标转为 grid 行列

这需要 mosaicCanvas 暴露其内部渲染参数。**最佳方案是在 mosaicCanvas 中新增 `getVisibleGridRange()` 方法**，因为它拥有所有内部参数，index.js 只需调用即可。

**Commit**: `fix: 重写快照导出坐标计算，修复拖动偏移和坐标系混淆`

### Fix 7: 问题 9 — vibrantScale observer 减少 deepClone 次数

**文件**: `src/components/mosaicCanvas/mosaicCanvas.js`

**问题**: `vibrantScale` observer 在 `isCropped` 路径中 deepClone 了 3 次全图 gridData。

**修改**: `reapplyColors` 是就地修改 gridData 的，而 `fullGrid` 已经是 clone 出来的，所以 `reapplyColors` 后直接赋值 `this.cachedOriginalGridData = fullGrid`，省掉第二次 clone。

需要确认 `reapplyColors` 确实是就地修改的（检查 `colorPipeline.js`），以及 `_applyGridPreset` 是否也就地修改输入。

```js
if (isCropped) {
  const fullGrid = this.deepCloneGridData(this.cachedOriginalGridData, origRows, origCols);
  this._pipeline.reapplyColors(fullGrid, origRows, origCols);
  // reapplyColors 就地修改 fullGrid，直接赋值无需再 clone
  this.cachedOriginalGridData = fullGrid;
  // _applyGridPreset 内部会 clone，所以 fullGrid 不会被 mutate
  const presetResult = this._applyGridPreset(fullGrid, origCols, origRows, presetVal);
  this.cachedGridData = presetResult.gridData;
  this.cachedGridInfo = { cols: presetResult.cols, rows: presetResult.rows, gridSize };
} else {
  this._pipeline.reapplyColors(this.cachedGridData, rows, cols);
  // 保存快照：需要 clone 因为 cachedGridData 后续可能被 mutate
  this.cachedOriginalGridData = this.deepCloneGridData(this.cachedGridData, rows, cols);
}
```

**Commit**: `perf: vibrantScale observer 减少一次 deepCloneGridData 调用`
